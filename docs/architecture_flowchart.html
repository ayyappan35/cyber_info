System Architecture — Flowchart

One real branching diagram of the whole platform — UI, all 4 entry paths, the Threat Router's 5-category fan-out, the Security LLM Discussion, policy, the MCP tool catalog, and the loop back to the UI. Same content as README.md's architecture diagram, drawn as an actual flowchart rather than stacked cards.

UI Gateway / evidence Routing / LLM Knowledge (RAG) policy MCP tools Verification async step (paused for approval)

Decision colors reuse the stage palette as a risk-level shorthand, not a stage label: green = pass, amber = caution, red = stop — that's why ALLOW/MITIGATE/BLOCK also carry ✓/⚠/✕ marks. Every action (including BLOCK) still passes through Policy and MCP Tool Authorization — Policy is what decides BLOCK stays BLOCK rather than getting stepped down, and any LLM-proposed remediation tool is still authorized independently. Dashed borders mark a step that pauses for something outside the automated pipeline (human sign-off).

Source: README.md's architecture diagram, security_gateway/gateway.py, threat_router.py, mcp_gateway.py.
