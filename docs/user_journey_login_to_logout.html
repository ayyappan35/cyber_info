Full Pipeline — Login to Logout

One continuous vertical flow: the real screen-by-screen UI journey (frontend/src/), expanded at the point a question is asked to show every step inside the AI Security Gateway — skill routing, knowledge retrieval, the LLM discussion, and MCP tool calling — before returning to the UI and, eventually, logout.

UI screen User choice / branch Evidence / control Knowledge retrieval (RAG) Security LLM Discussion / MCP tools Session ends
1

Landing UI

Unauthenticated visit → ProtectedRoute has nothing to protect yet, so App.jsx routes to /login (or /signup for a new account).

frontend/src/pages/Login.jsx · Signup.jsx
2

Submit credentials Backend

Username/password (+ email on signup) posted to the API. Password check stays plain bcrypt/JWT code — the AI Security Gateway separately reasons about the attempt pattern (failed-attempt count, lockout state) via the authentication category, independent of whether the password itself was right.

POST /api/auth/login or /signup · auth_router.py
3

Session established State

JWT access token returned; AuthContext persists token, username, role to localStorage and flips isAuthenticated to true. First account ever created is auto-promoted to role: admin.

frontend/src/context/AuthContext.jsx :: login() / signup()
4

Redirect to workspace UI

ProtectedRoute now passes → /chat renders: Sidebar (conversation list, New chat, Admin Dashboard button if admin, theme toggle, account + Sign out) alongside the Chat window.

GET /api/conversations on load
5

Chat workspace User loop

The user stays here for the rest of the session, looping between actions — this is the app's steady state, not a one-way step.

New chat / select / delete

Switches or clears the active conversation.

Toggle theme

Sun/moon icon — dark ⇄ light, ThemeContext.jsx.

Send a message

Goes through the full Security Gateway pipeline — steps 6–15 below.

Admin Dashboard

Admins only — see step 16.

↻ repeats for the length of the session
6

User asks a question UI

Typed into the Chat window and submitted — this is the trigger for everything below. The message is sent immediately as a streaming request; the UI shows a live "Thinking…" status as each stage below reports progress.

POST /api/query/stream · Chat.jsx :: handleSend()
7

Chat agent tool-use loop Agent

Answers using up to 3 tools before anything is checked for safety: search_knowledge_base (internal KB), get_skill_methodology (this system's own detection knowledge), search_external_web (live DuckDuckGo lookup, entity/topic queries only).

backend/pipelines/chat_agent.py
8

Evidence gathering

Regex signals computed over the question and everything actually retrieved — override language, extraction language, PII patterns, imperative-in-context language. Facts, not the LLM's opinion.

gateway.py :: gather_chat_evidence()
9

Supervisor Agent → skill selection Routing

Dispatches to every matching skill under skills/llm/ and skills/rag/ at once — prompt-injection and rag-poisoning always run as the baseline; jailbreak, model-extraction, pii-exposure, external-api-abuse join only when their own pattern matches.

supervisor_agent.py :: route_chat()
10

Knowledge retrieval (RAG) Threat KB

Query built from the matched skill id(s), searched against the security_threat_knowledge Chroma collection — similarity search, reranked, top-4 chunks.

prompt_injection.md
indirect_prompt_injection.md
rag_poisoning.md
mitre_atlas.md / data_exfiltration.md
knowledge/cyber_defence/*.md · threat_knowledge.py
11

Security LLM Discussion Ollama / Claude

One real LLM call, fed the matched skills' methodology + retrieved knowledge together. Returns a Pydantic-validated decision — rejected outright if malformed, never coerced.

action · confidence · threat_indicators · reasoning · required_tools
12

policy clamp

A skill's floor can only raise the action toward BLOCK; a ceiling can only cap it toward ALLOW. Then policy.py checks security_gateway_policy.yaml: is this action enabled for the category, and does confidence clear the minimum? The LLM can never edit this file or bypass it.

detection.py :: apply_floor()/apply_ceiling() · policy.py :: clamp_action()
13

MCP tool calling Tool Authorization Gateway

The clamped action fires its policy effect via mcp_tools/; any specific tool the LLM additionally proposed is independently checked against the 13-tool catalog — category scope, rate limit, then executed or queued.

quarantine_documentauto
get_document_provenanceauto
remove_vectorapproval
disclose_pii_answerapproval
security_gateway/mcp_gateway.py :: authorize_and_execute()
14

Verification + audit SIEM

Real state is re-read (sandbox row actually exists?) before anything is reported successful — never trusted just because the write call didn't raise. Decision, reasoning, confidence, and matched skill ids logged for the Admin Dashboard.

gateway.py :: _verify() · siem_tool.py :: log_decision()
15

Response returns to the UI Outcome

Back in Chat.jsx — the streamed result lands as one of two outcomes:

ALLOW / MITIGATEReal answer + sources shown; live agent trace available.
BLOCKSecurity LLM Discussion's own reasoning (step 11) shown as the refusal — a PII case instead shows a pending-admin-approval badge.
↻ back to step 5 — the user can send another message
16

Admin Dashboard UI, admin only

Training/upload panel plus Overview, Sandbox, Blocked, Events, Chain, Users, and Pending Tool Approvals tabs — the same Sidebar toggle switches back to Chat at any time.

frontend/src/components/TrainingPanel.jsx
17

Sign out Ends session

Best-effort server-side revoke first (token's jti added to revoked_tokens so it can't be reused even before it expires) — then local state is cleared regardless of whether that call succeeded; the user's intent to sign out always wins.

POST /api/auth/logout · AuthContext.jsx :: logout()
18

Back to Login UI

localStorage cleared, isAuthenticated false → every route falls back to /login. Session fully ended client- and server-side.
