files (uploads)

The upload path's gateway check is currently disabled in this build (README, 2026-08-25 owner decision) — every upload embeds unconditionally. The rows below describe what runs when it's re-enabled.
SkillRouting / floorKnowledgePolicy
malicious-pdf default Fallback for .pdf/.md/.txt/.xlsx. Two independent floors: 2+ active-content byte markers (/JS, /OpenAction...) → MITIGATE; per-chunk ML injection-classifier score ≥0.75 → MITIGATE. no file-security knowledge doc exists anywhere in knowledge/ category default
malicious-docx Routes on .docx extension. Floor: VBA macro present → MITIGATE minimum, regardless of visible text. no file-security knowledge doc exists category default
archive-bomb Routes on .zip extension. Floor: 100x+ compression ratio → hard BLOCK; 5,000+ entries → hard BLOCK. no file-security knowledge doc exists category default

agents (A2A)

The A2A path never runs the chat agent's knowledge-base search at all (agent_router.py calls the gateway directly) — so owasp_agentic/agent_tool_misuse_and_injection.md, the one business-KB doc that's actually about this, is never consulted for an A2A decision. The threat-knowledge collection is the only grounding these skills ever get, and none of its 5 files are agent/A2A-specific.
SkillRouting / floorKnowledgePolicy
tool-abuse default Baseline on every A2A message. Floor: requested tool outside the sender's registered allowed_tools → hard BLOCK (registry is the source of truth, verified live). data_exfiltration.mdindirect_prompt_injection.mdrag_poisoning.md (closest available, not dedicated)

privilege-escalation Routes when role changed with no audited change event. Floor: same condition → hard BLOCK. same gap as tool-abuse category default — no response.yaml file exists for this skill
intent-drift unwired No routing rule at all — never selected by route_multi(). Would need a goal_alignment_score this build doesn't compute (see its SKILL.md). n/a n/a
Reading the gaps honestly: files and agents have zero dedicated threat-knowledge documents — the Security LLM Discussion still runs and still reasons well (verified live — see docs/live_test_results.html), but it's doing so on deterministic evidence + its own general reasoning, not on knowledge written for that specific attack class. That's not a bug to silently paper over: it's exactly the kind of thing knowledge/cyber_defence/ should grow to cover next.
